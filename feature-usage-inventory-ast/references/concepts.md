# Concepts

Используй эти роли для любого домена. Не подставляй в инструкцию конкретные названия фичи, пока пользователь их не дал.

## Роли

- Целевая сущность: функция, свойство, модель, enum, формат, сценарий или поведение, которое инвентаризируется.
- Прямая модель: класс, структура, schema, interface или record, где сущность определена напрямую.
- Владелец: объект, который хранит, содержит, наследует, применяет или передает целевую сущность.
- Контейнер: промежуточная модель, которая группирует несколько свойств и делает целевую сущность доступной другим владельцам.
- Получатель: объект или семейство объектов, для которых целевая сущность становится частью поведения.
- Старт сценария: место, где пользователь, API, importer, loader, test или background flow инициирует изменение или чтение.
- Мост: код, который переводит сущность между слоями, форматами, редакторами, runtime state или serialized state.
- Consumer: код, который принимает уже подготовленную сущность и использует ее для поведения, rendering, export, validation или persistence.
- Output: видимый render, exported artifact, saved binary/json/xml, clipboard payload, API response, preview или side effect.

## Типы Связей

Фиксируй тип связи явно:

- defines: объявляет модель или поле;
- owns: хранит как часть объекта;
- contains: содержит через вложенный контейнер;
- inherits/resolves: получает через defaults, styles, themes, parent chain или computed state;
- transforms: преобразует формат или units;
- forwards: передает дальше без владения;
- validates: проверяет допустимость;
- serializes/deserializes: пишет или читает persisted representation;
- renders/exports: превращает в output;
- mutates: изменяет state;
- tracks: участвует в history/undo/redo/change model;
- tests: покрывает тестом или fixture.

## Классификация Evidence

- Direct evidence: файл содержит имя целевой сущности или ее persisted/API alias.
- Structural evidence: файл содержит владельца/контейнер/consumer, через который сущность проходит.
- Behavioral evidence: файл меняет output или runtime поведение без прямого имени сущности.
- Negative evidence: зона проверена, но релевантного использования не найдено.
- Noise: совпадение есть, но не связано с целевой сущностью.
