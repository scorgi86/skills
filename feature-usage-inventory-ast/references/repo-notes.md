# Repo Notes

Эти заметки нейтральны к функциональности и помогают в больших mono-repo.

## Linked Directories

Если каталог содержит linked directories, обычный `rg` может пропустить часть дерева. При подозрении на ссылки используй `rg -L` и явно отметь это в отчете.

## Фильтры Для Первичного Поиска

В больших репозиториях разделяй основной поиск по исходному коду и проверку шумовых зон.

Типовые зоны для исключения из основного поиска:

- `node_modules`, `vendor`, сторонние snapshots;
- `.cache`, `.webpack-cache`, временные каталоги;
- `dist`, `build`, `out`, `coverage`, minified bundles, `*.map`;
- локализации, help/search indexes, документационные примеры;
- большие бинарные пакеты и generated-файлы, если они не являются предметом исследования.

Исключение из основного поиска не означает, что зона не проверена. Если зона может быть релевантна persisted format, fixture, публичному контракту, справке пользователя или совместимости, проверь ее отдельным запросом и явно запиши результат.
## Границы Слоев

При поиске разделяй слои:

- product/web/app UI;
- public API and command layer;
- core model/state;
- format import/export;
- rendering/preview/print;
- tests/fixtures;
- build/generated/vendor.

Не переноси вывод из одного слоя на другой без evidence.

## Noise

В больших репозиториях часто встречается шум:

- autogenerated bundles and maps;
- minified assets;
- vendor snapshots;
- localization-only strings;
- CSS names without model/output connection;
- documentation examples that are not executed.

Шум полезно учитывать только как checked/excluded evidence.
