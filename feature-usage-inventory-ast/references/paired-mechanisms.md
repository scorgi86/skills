# Эталонные Пути И Отсутствующие Пути

Используй этот справочник, когда пользователь просит оценить зону доработки, найти связанные объекты, проверить полноту отчета или понять, куда целевая сущность должна быть встроена.

## Цель

Найти не только места, где целевая сущность используется сейчас, но и ожидаемую карту внедрения через уже реализованные пути кодовой базы.

Эталонным путем может быть:

- ближайший аналог;
- соседнее свойство;
- общий контейнер;
- существующий получатель;
- lifecycle-путь чтения, изменения, отрисовки, сохранения или экспорта;
- архитектурный контракт;
- готовая ветка, где работа уже выполнена.

Если прямого аналога нет, используй несколько частичных эталонов по слоям.

## Порядок Работы

1. Определи имена целевой сущности.
2. Определи один или несколько эталонных путей.
3. Выполни поиск по целевой сущности и эталонным путям.
4. Сравни слои: модель, API, контроллеры, получатели, отрисовка, сохранение, история, тесты.
5. Для каждой строки укажи статус подтверждения.
6. Преврати отсутствующие ожидаемые пути в список вероятных пробелов реализации.

## Нельзя

- Нельзя выдавать подтверждение по эталону за использование целевой сущности.
- Нельзя называть отсутствующий путь ошибкой, если контекст задачи этого не подтверждает.
- Нельзя останавливаться на модели или сериализации, если эталон показывает API, отрисовку, контроллеры, получателей или пользовательский путь.
- Нельзя требовать единственный близкий аналог: если аналога нет, собирай эталонную карту из нескольких частичных путей.
