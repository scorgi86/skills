# Recipient Fan-out

Fan-out нужен, когда целевая сущность является свойством, контейнером или частью shared model. В этом случае главный риск - найти только один объект, хотя изменение затронет все семейства получателей.

## Как Искать Получателей

1. Найди контейнер или владельца, через который целевая сущность попадает в другие объекты.
2. Найди все типы объектов, которые могут владеть этим контейнером.
3. Для каждого типа проверь отдельные пути:
   - creation/defaults;
   - user/API mutation;
   - import/deserialization;
   - recalculation/cache;
   - rendering/preview;
   - export/serialization;
   - copy/paste;
   - tests/fixtures.
4. Отметь, где путь общий, а где расходится по типу объекта.

## Вопросы Полноты

- Есть ли общий base class или interface, который скрывает реальные получатели?
- Есть ли dispatch по object type в render/export/serializer?
- Есть ли объекты, которые хранят свойство, но игнорируют его при output?
- Есть ли fallback/default, который применяется только к части получателей?
- Есть ли продуктовые слои, где сценарий общий, но bridge разный?
- Есть ли fixtures, где сущность присутствует только как persisted data?
