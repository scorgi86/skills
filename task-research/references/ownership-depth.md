# Ownership Depth

Порядок использования показывает, насколько далеко целевая сущность находится от места реального поведения.

## Первый Порядок

Прямое использование целевой сущности:

- определение поля/класса/enum;
- прямое чтение или запись;
- прямой serializer/deserializer;
- прямой renderer/exporter;
- прямой public API.

## Второй Порядок

Целевая сущность используется как свойство другого объекта:

- контейнер хранит целевую сущность;
- владелец хранит контейнер;
- adapter принимает объект-владелец и косвенно несет целевую сущность;
- UI/API меняет владельца, а не саму сущность.

## Третий Порядок

Владелец второго порядка становится частью более крупного объекта или сценария:

- document/page/scene/item/entity owns object with target container;
- selection/workflow operates on the owner family;
- render/export dispatch выбирает тип владельца и только потом достигает целевой сущности.

## N-й Порядок

Продолжай подниматься, пока не достигнуты:

- старт пользовательского или API сценария;
- importer/loader entry point;
- render/export entry point;
- persistence entry point;
- product/editor boundary;
- test fixture boundary.

## Правило Остановки

Нельзя останавливаться на первом найденном владельце, если:

- владелец является общим контейнером;
- есть несколько семейств получателей;
- render/export dispatch зависит от типа получателя;
- UI/API сценарий общий, но runtime path разный;
- serializer path и render path расходятся.
