# Task Code Review

`task-code-review` проверяет полный набор изменений ветки относительно требований задачи и находит доказуемые дефекты, отклонения и пробелы реализации. Навык не изменяет код и Git-историю: результатом работы является отчёт ревью либо структурированный handoff делегата.

Навык рассчитан на ревью задачи, ветки или согласованного межрепозиторного изменения. Для проверки отдельного файла, коммита или произвольного фрагмента кода следует использовать обычное code review без этого навыка.

## Быстрый старт

Полное ревью одной ветки:

```text
Используй $task-code-review и проверь ветку feature/metrics относительно develop.
Требования находятся в task.md. Целевой репозиторий: C:\work\product\sdkjs.
```

Межрепозиторное ревью:

```text
Используй $task-code-review в режиме coordinator-review.
Проверь реализацию требований из приложенного документа в репозиториях sdkjs и web-apps.
Base: develop, head: feature/metrics-contract.
```

Проверка делегированного среза:

```text
Используй $task-code-review в режиме delegated-review.
Проверь только переданный review packet и верни compact handoff координатору.
```

Для полного ревью нужно передать содержательное описание задачи, целевые репозитории и Git-границы либо refs, из которых их можно однозначно получить. Делегированному ревью нужен сформированный координатором review packet.

## Режимы

### `coordinator-review`

Режим по умолчанию. Координатор отвечает за весь scope и итоговый пользовательский вердикт. Он:

- читает требования и вложения;
- фиксирует Git-снимок каждого репозитория;
- связывает требования с изменениями;
- исследует реализацию, потребителей и тесты;
- при необходимости делегирует независимые срезы;
- объединяет доказательства и формирует итоговый отчёт.

Точный контракт находится в [references/coordinator-review.md](references/coordinator-review.md).

### `delegated-review`

Делегат работает только внутри переданного packet, не отвечает за полноту всей ветки и не выносит глобальный вердикт. Результат — компактный структурированный handoff со статусами требований, findings, проверенными областями и запросами на расширение scope.

Роль субагента сама по себе не включает этот режим: координатор должен явно указать `mode=delegated-review` и передать packet. Точный контракт находится в [references/delegated-review.md](references/delegated-review.md).

## Стек работы

Метки показывают, кто выполняет каждый шаг: `[ИИ]`, `[скрипт]` или `[Git]`.

```text
Пользовательский запрос
└── [ИИ] Выбрать режим и проверить обязательные входы
    ├── coordinator-review
    │   ├── [ИИ] Прочитать описание задачи и вложения
    │   ├── [ИИ] Атомизировать требования и назначить Requirement IDs
    │   ├── [ИИ/Git] Подтвердить repository identity и актуальные boundaries
    │   ├── [скрипт] snapshot
    │   │   ├── [Git] Проверить immutable commit objects
    │   │   └── [Git] Получить полный A/M/D/T inventory между boundaries
    │   ├── [ИИ] Связать требования, changed files и применимые риски
    │   ├── [ИИ] Исследовать поведение, consumers и тесты
    │   ├── [ИИ] При необходимости подготовить независимые review packets
    │   │   ├── [скрипт] validate-packet
    │   │   └── delegated-review
    │   │       ├── [скрипт] validate-packet
    │   │       ├── [скрипт] snapshot для каждого repository из packet
    │   │       ├── [ИИ] Исследовать назначенный срез
    │   │       └── [ИИ] Сформировать compact handoff
    │   ├── [скрипт] validate-handoff для каждого результата делегата
    │   ├── [ИИ] Проверить истинность evidence и глобальную полноту scope
    │   └── [ИИ] Сформировать итоговый вердикт и отчёт пользователю
    │
    └── delegated-review
        ├── [скрипт] validate-packet
        ├── [скрипт] snapshot для каждого repository из packet
        ├── [ИИ] Связать назначенные requirements с files/scopes
        ├── [ИИ] Исследовать код до наблюдаемой границы поведения
        ├── [ИИ] Зафиксировать findings, gaps и scope requests
        └── [ИИ] Вернуть compact handoff без глобального вердикта
```

## Разделение ответственности

| Исполнитель | Что делает | Чего не делает |
|---|---|---|
| ИИ | Извлекает требования, выбирает направления исследования, читает код, проверяет достижимость сценариев, оценивает достаточность evidence и формирует findings | Не считает успешный тест автоматическим доказательством полного требования |
| `snapshot` | Проверяет доступность заданных immutable Git boundaries и строит отсортированный список A/M/D/T | Не выполняет fetch, не подтверждает remote freshness и не читает смысл изменений |
| `validate-packet` | Проверяет структуру packet, уникальность IDs и внутренние ссылки | Не определяет достаточность scope и не ревьюит код |
| `validate-handoff` | Проверяет согласованность handoff с packet и вычисляемый `scope_status` | Не подтверждает истинность evidence и не выносит глобальный вердикт |
| Git | Предоставляет commit objects и diff для зафиксированных boundaries | Не определяет требования и корректность реализации |

После успешной структурной проверки ИИ не повторяет тот же gate вручную без конкретного противоречия. Это сокращает механическую работу, но не заменяет семантическое ревью.

## Результат

Полный режим начинает отчёт одним из вердиктов:

- `ПРОХОДИТ ПРОВЕРКУ` — все применимые требования подтверждены и доказуемых дефектов нет;
- `НЕ ПРОХОДИТ ПРОВЕРКУ` — найден дефект, отклонение или нереализованное требование;
- `ПРОВЕРКА НЕ ЗАВЕРШЕНА` — без доказанного дефекта отсутствует обязательный вход, обязательное требование невозможно подтвердить либо diff нельзя построить и исследовать.

Делегированный режим возвращает только compact handoff со `scope_status`: `passed`, `failed` или `blocked`. Этот статус относится к назначенному срезу и не является вердиктом всей задачи.

## Автоматизированный fast path

Если доступны Node.js и [scripts/review-tools.js](scripts/review-tools.js), навык использует три dependency-free команды:

```text
node scripts/review-tools.js snapshot --input <json-file|->
node scripts/review-tools.js validate-packet --input <json-file|->
node scripts/review-tools.js validate-handoff --input <json-file|->
```

Их runtime-контракт и коды завершения описаны в [references/automation.md](references/automation.md). При недоступности CLI навык использует ручной workflow выбранного режима.

## Ограничения и безопасность

- Навык не изменяет рабочее дерево, локальные ветки, историю, требования и вложения.
- Незакоммиченные изменения не входят в ревью без явного указания пользователя.
- Fetch допустим только для точечного получения необходимых объектов; `pull`, `checkout`, `merge`, `rebase`, `reset` и очистка запрещены.
- Делегат не выполняет remote query или fetch и не выходит за repositories/snapshots packet.
- Тесты и сборки запускаются в изолированной от рабочего дерева среде; внешние записи допустимы только в явно выделенную одноразовую test-среду в разрешённом scope. Если безопасность изоляции или внешних эффектов не доказана, требуется отдельное разрешение пользователя.
