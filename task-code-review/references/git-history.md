# История и интеграция

Читать при продвижении base после merge base, частичной интеграции, rewrite/rebase/force-push, revert, историческом риске или явном запросе на аудит истории.

## Границы

Не считать текущий merge base исходной границей задачи автоматически. Определить её по graph, исходной base SHA, PR/MR metadata, задаче или указанию пользователя. Если принадлежность необходимых коммитов доказать нельзя, считать исторический scope неподтверждённым.

Разделять:

- current-tree diff относительно актуального merge base;
- task history от доказанной исходной границы, включая уже интегрированные и отменённые коммиты;
- published history из authoritative PR/MR events или server audit, когда есть признаки переписывания опубликованной истории.

При свидетельстве rewrite и недоступной authoritative истории использовать `published unknown`; не заявлять полноту опубликованной истории.

## Интеграция с base

Выполнить read-only three-way анализ head с актуальным base tip, например `git merge-tree`. Рассмотреть релевантные base-only изменения. Подтверждённый конфликт или дефект интеграции считать defect; невозможность исследовать обязательную интеграцию без доказанного дефекта фиксировать как обязательный gap. Не выполнять реальный merge в рабочую ветку.

## Исторические эффекты

Проверить покоммитные изменения на опубликованные секреты, опасные миграции и иные внешние эффекты, не исчезающие после revert.

Для сохраняющегося эффекта создать отдельное замечание: указать commit/строки, путь возникновения, статус `активен`, `устранён` или `неизвестно` и доказательство ротации/компенсации. `Активен` является defect; `неизвестно` — обязательным gap, если уже нет доказанного дефекта. `Устранён` показать как закрытый исторический риск. Один revert не доказывает устранение.

Результат применять по выбранному режиму:

- в `coordinator-review` defect ведёт к `НЕ ПРОХОДИТ ПРОВЕРКУ`, а обязательный gap без defect — к `ПРОВЕРКА НЕ ЗАВЕРШЕНА`;
- в `delegated-review` использовать локальный приоритет `failed`/`blocked`, вернуть evidence координатору и не выводить глобальный вердикт. Если исследование требует repository/snapshot вне packet, создать `scope_request`.
