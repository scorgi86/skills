# Семантическая инвентаризация

Читать при изменении публичных или разделяемых контрактов, форматов, схем, моделей данных, persistence, config keys, feature flags либо межрепозиторного поведения.

Для каждого изменённого контракта исследовать:

- определения, чтения и записи;
- callers/callees и точки старта сценариев;
- прямых и косвенных consumers;
- сериализацию, сохранение, импорт и экспорт;
- конфигурационные bindings и значения по умолчанию;
- переходы через границы компонентов и репозиториев;
- тесты и существующие эталонные пути похожего поведения.

Кандидатов подтверждать исходным кодом. Непроверенную ветвь фиксировать как gap и переводить затронутое требование в `невозможно подтвердить`.

Прослеживать поведение до наблюдаемой точки, а не останавливаться на непосредственном вызове.

Результат применять по выбранному режиму:

- в `coordinator-review` обязательный gap без доказанного дефекта ведёт к `ПРОВЕРКА НЕ ЗАВЕРШЕНА`; при наличии дефекта сохранять `НЕ ПРОХОДИТ ПРОВЕРКУ` и перечислять gap в ограничениях. Для обязательного репозитория вне scope запросить его включение либо доказуемое исключение;
- в `delegated-review` использовать локальный приоритет `failed`/`blocked` из делегированного контракта. Для обязательного repository/snapshot вне packet создать `scope_request`, не исследовать его без нового packet и не выводить глобальный вердикт.
