# 05 — Findings

Создавать записи только по доказанным недостаткам требований.

Внутренняя модель:

```text
findingId
requirementRefs[]
evidenceRefs[]
dependsOnRequirementRefs[]
remark
status
assumption?
```

Для `fast` не создавать нормативные findings: выводить только кандидатов на замечания.

Для `standard` и `full` назначать статус только по `references/development-conclusion-rules.md`.

При обнаружении новой ссылки или источника зарегистрировать его по `workflows/02-map.md`, повторно открыть source gate и завершить его разбор до продолжения.

## Допущение

Для замечания, которому нормативные правила требуют допущение, хранить:

```text
text
revision
confirmationEvidenceRef?:
  evidenceArtifactId
  revision
confirmedAssumptionRevision?
```

Подтверждение действительно, только если:

- доказательное событие существует и активно;
- имеет тип `USER_EVENT`;
- revision в ссылке совпадает с revision доказательного события;
- его statement явно подтверждает конкретный текст или revision;
- `confirmedAssumptionRevision` совпадает с текущей revision допущения.

Изменение текста допущения:

- создаёт новую revision;
- очищает `confirmationEvidenceRef` и `confirmedAssumptionRevision`;
- повторяет этапы findings, report и validate;
- если новое допущение меняет трактовку требования или конфликта, повторяет completeness, consistency и зависимые этапы.

Простое подтверждение неизменного текста повторяет только report и validate.

Изменение revision, деактивация или удаление доказательного события подтверждения всегда очищает подтверждение допущения. Новую revision события нельзя автоматически переиспользовать, даже если statement похож.

## Дефект комплекта требований

Если обязательный источник подтверждённо отсутствует, создать замечание только при наличии доказательств из `workflows/04-consistency.md`.

Такому замечанию всегда присваивать статус `Блокирующее`; допущение не формировать.

Непереданный или технически нечитаемый источник без подтверждения отсутствия не является замечанием к требованиям; запросить вход через intake.

## Вывод в Карточку

Служебные поля, revisions и доказательные идентификаторы не выводить. В Карточку переносить только поля из `references/report-schema.md`.

Не объединять независимые недостатки и не добавлять советы по реализации или тестированию.
